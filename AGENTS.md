# AGENTS.md — `HiveMind-js`

Guidance for AI coding agents (and humans) working in this repository. Read it
fully before making changes. It encodes conventions that are not obvious from the
code and that, if ignored, produce work that will be rejected.

## Repo

JavaScript client for the HiveMind protocol, up to protocol v3 (Noise with
argon2id PSK derivation), running in both the browser and Node.js 18+. Part of
the [HiveMind](https://github.com/JarbasHiveMind) ecosystem — a protocol for
connecting satellite devices to a hub running
[OpenVoiceOS](https://github.com/OpenVoiceOS). The hub is
[HiveMind-core](https://github.com/JarbasHiveMind/HiveMind-core); the wire
protocol and Noise crypto spec (HIVEMIND-CRYPTO-1) live in the architecture
docs. Uses native Web Crypto (`crypto.subtle`) for X25519/SHA-256/HMAC/AES-GCM
plus `@noble/ciphers` and `@noble/hashes` for ChaCha20-Poly1305 and argon2id,
giving full cipher-suite parity with the reference Python client.

## Layout / build / test

- Distributable sources: `static/js/hivemind.js` (CJS/browser) and
  `static/js/hivemind.mjs` (ESM) — both are hand-written, not build output;
  keep them in sync when changing behavior. Tests live in `test/` (check
  before adding — do not create a second test directory).
- Install with `npm install` (runtime deps are `@noble/ciphers` and
  `@noble/hashes`; `ws` is a dev-only dependency, used to supply a Node
  `WebSocket` global for tests since Node has none built in).
- Run the suite in the foreground: `npm test` (`node --test test/*.test.js`).
  `npm run test:e2e` additionally spins up `test/e2e/loopback_hub.py`, a
  Python HiveMind-core-shaped loopback hub — needs the deps in
  `test/e2e/requirements.txt` and exercises a real handshake round trip, not
  just mocked WebSocket frames.
- `package-lock.json` is committed for reproducible CI installs; this is the
  npm-ecosystem equivalent of the floor-pins policy below, not a
  Python-style lockfile-of-record — `package.json` ranges are still the
  source of truth for what a consumer resolves.

## Working agreement (org-wide law)

- **Git identity is always** `JarbasAi <jarbasai@mailfence.com>`. Never set a
  per-repo override.
- **Never push `dev` or `master`.** Work on a feature branch and open a
  **draft** PR into `dev`. A human merges. You do not merge your own PRs.
- **Never merge or modify `Release X → master` PRs.** They are the maintainer's
  stable-release mechanism, generated by automation.
- **One commit per PR** (squash before pushing). Conventional commits; `feat:`
  only for a user-visible new capability. `fix:`, `docs:`, `chore:`, `ci:`
  otherwise.
- **Disclose AI authorship.** Every PR/issue/comment an agent writes carries, at
  the top: `> 🤖 Auto-generated by <model> via Claude Code — NOT human-reviewed.
  Verify before acting.` PR bodies are plain human prose (3–6 short paragraphs),
  no tables or section-symbol spray.
- **Never edit someone else's** issue, PR description, or comment. Add a comment
  instead; on your own PRs, edit the body rather than piling on comments.
- Keep durable text (README, docs, PR bodies, comments) timeless and standalone:
  no dates, no "currently/now/new", no meta-commentary about the edit itself.
- No scratch files, committed virtualenvs, `__pycache__`, `.pyc`, `.egg-info`,
  `node_modules`, or build artifacts in a PR. `git show --stat` shows only
  intended files.

## Dependencies

- **Floor pins only** (caret ranges `^X.Y.Z` are npm's floor-pin equivalent),
  bumped when a feature or fix is actually needed — with a one-line comment
  saying why. No pinning to an exact version unless a specific released
  version is genuinely broken (say which and why).
- Runtime deps stay minimal and audited (`@noble/ciphers`, `@noble/hashes`);
  do not add a dependency for something Web Crypto or a five-line helper
  already covers.
- Never install from a git URL — depend on a published npm release.
- Apache-2.0. Do not add GPL/AGPL dependencies.

## Tests

- Adversarial by default. A regression test must **fail before the fix and pass
  after** — prove it by reverting only the source (`git apply -R`, never
  `git stash` across worktrees) and watching the test flip.
- Tests must be mutation-proof: gutting the feature must fail the test. A test
  that only asserts a mock method was called, without asserting the real
  cryptographic/wire output, is weak — note it.
- Never skip a test because an optional dependency is missing.
- CI green is permission to review, not to merge. A non-trivial change gets an
  adversarial review before it lands.

## Repo-specific rules

- This client speaks the HiveMind wire protocol to the hub; keep wire
  compatibility with the reference Python client — suite negotiation order,
  message envelope shape, and the v0-v2 legacy handshake fallback must match.
- Noise static-key persistence: `connect()` generates a static X25519 key when
  none is supplied and remembers it keyed by `host`/`port`/`accessKey` —
  `localStorage` in the browser, an in-memory process-lifetime cache in
  Node.js. A reconnect must reuse the persisted key, never regenerate one,
  because the server pins a client's static key on first use (TOFU) and a
  fresh key self-locks the client out. Node.js has no cross-restart identity
  persistence today (no `localStorage`, and the library deliberately will not
  write key material to disk on its own) — callers that need a Node process
  identity to survive a restart must pass `noiseStaticKey` themselves; do not
  silently add disk persistence without discussing the security trade-off
  first.
- Bad credentials must fail fast: a WebSocket close with code `1008` before
  the handshake reaches READY is treated as fatal and surfaces through
  `onHiveError`, fired before `onHiveDisconnected`. The client does not
  auto-reconnect on any close — do not add unbounded or unconfirmed retry
  logic; a caller-driven reconnect is expected to reuse the persisted key
  above, not spin forever against a hub that just rejected it.
- `ovos.utterance.speak` and the legacy `speak` bus message type both route
  through `onMycroftSpeak` — keep that dual mapping when touching message
  dispatch, deployed hubs still emit the legacy type.
- Keep `hivemind.js` (CJS/browser) and `hivemind.mjs` (ESM) behaviorally
  identical; a fix in one without the matching edit in the other is a partial
  fix.
